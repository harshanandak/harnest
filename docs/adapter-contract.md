# Adapter contract

An adapter owns one complete downstream workflow. It does not choose between OpenCode, Pi, Cursor, Claude, Codex, Gemini, Amp, and a registered generic ACP agent per phase.

```js
const adapter = new Adapter(options);
const output = await adapter.run(request, { signal, onProgress });
const acknowledgement = await adapter.control(command);
```

`request` is the normalized handoff request from `src/protocol.mjs`. `run` must:

1. launch only its assigned harness;
2. pass the task, context capsule, FlowSpec, route, cwd, policy, and request/context identifiers;
3. report the resolved harness/model/session identity;
4. distinguish abort, transport failure, downstream failure, and success;
5. return a JSON object with `sessionId`, `workflowRunId`, `route`, `result`, and `usage`.

`result` must contain at least `finalText`; it may also contain `summary`, `evidence`, `artifacts`, `files`, `tests`, and `risks`. `receipt.routingDecision` is produced before adapter launch and contains only bounded policy scopes/rule IDs, candidate IDs, rejection codes, and score components—never task/context text or credentials. Raw harness event arrays never cross the parent receipt boundary; adapters return a bounded `eventSummary` instead. Parent-visible strings, arrays, and taskflow text are hard-bounded. A successful process with no final downstream output—or a terminal result that misses the request's completion contract—is a failure.

Pi graph requests must produce a genuine Taskflow terminal result. Unrelated assistant text, agent catalogs, plans, and accepted prompts cannot satisfy a saved FlowSpec. Plain prompt-only requests (no `workflow.spec` and no `workflow.nodes`) execute natively in a single session—no Taskflow package or `/tf` command is required. Explicit Taskflow compatibility requests are the only ones that resolve or load the optional packages, and a missing package fails before launch with `missing-optional-dependency`. `workflow.nodes` uses Pi's deterministic saved-flow translation; OpenCode currently requires `workflow.spec` and rejects `workflow.nodes` before launch rather than silently running it as a plain prompt.

Adapters accept dependency injection for their executable and spawn function so contract tests never spend model tokens.

## Prompt caching and usage

Prompt envelopes place stable context before per-attempt task and request identifiers. OpenCode workflow phases include the shared context once. Each independent phase still receives its required context; a session ID alone is not proof that a downstream session already contains it. Provider cache hits must be measured from reported usage, not inferred from this prompt layout.

`usage` keeps the adapter's existing shape. The additive `usageSummary` reports inclusive `inputTokens` only when the provider's semantics and counters establish that total, plus `uncachedInputTokens`, `outputTokens`, `cacheReadTokens`, `cacheWriteTokens`, and `costUsd`. `inputSemantics` describes the original input counter. A missing metric is `null`; a reported zero remains zero. Cursor and unrecognized Pi usage shapes do not establish an inclusive input total. Cache-read counts do not establish how a subscription charges its limits.

`usageAttempts` records each attempt's job, route, state, raw usage, and normalized summary. Progress counters are cumulative snapshots and replace earlier observations rather than being summed. Closed attempts reject late progress. `resumeOf` links a resumed job to its parent; carried attempt history and `usageTotals` expose prior consumption. `usageAttemptsDropped` counts omitted older entries. Totals with `partial: true` are reported lower bounds, not complete consumption estimates; inspect `reportedAttempts` and `unreportedAttempts` as well as individual metrics.

## Execution and streaming

The shared process runner drains stdout/stderr while retaining diagnostic tails of 1 MiB and 64 KiB respectively. Results and errors report total byte counts and truncation flags. Adapters parse completion, identity, usage and failure events incrementally; final output must not depend on a retained diagnostic tail. A streaming line larger than 2 MiB fails with `kind: "output-limit"`. `maxStdoutBytes`, `maxStderrBytes` and `maxLineBytes` accept positive safe-integer byte limits for direct runner callers. Cursor rejects truncated plain-text output rather than treating the tail as a complete answer, and incomplete protocol JSON cannot use the plain-text fallback. Asynchronous stdin failures settle through the process error path after child cleanup.

OpenCode and Pi fold event summaries online. They retain at most 256 unique event-type names and report the last 20 in first-occurrence order. Their retained final-answer candidates are capped at 1,048,576 characters; an oversized candidate may be replaced by a later valid authoritative answer. A required final answer exceeding the 64,000-character receipt limit fails explicitly. Pi separately bounds JSONL framing to 2 MiB and stderr to a 64 KiB tail.

Progress consumers return their persistence Promise to apply backpressure. The shared runner invokes callbacks in line order, then awaits bounded groups of at most 100 lines or 64 KiB before reading more stdout. A larger complete line occupies a group alone. Both success and nonzero exit wait for accepted callbacks; the original timeout remains active after child close. Callback throws and rejections fail through the transport path. Pi serializes callback delivery and bounds unread input to 4 MiB or 256 chunks. Adapters propagate progress promises instead of retaining an unbounded queue of pending writes.

Claude, Cursor, Codex, Gemini, Amp, and generic ACP reject `workflow.spec` and `workflow.nodes` before launch. They do not execute Taskflow graphs. Pi checks its reported active provider/model before sending a prompt, including when the request relies on profile defaults. Named Claude routes and nested phase overrides are rejected outside Claude Code. Opaque automatic model selection and saved extension-specific profile resolution still require host-level verification.

Codex validates that `cwd` is inside a Git worktree before launching inference. It sends the complete prompt through stdin using the `-` prompt argument, then closes stdin. Sandbox, directory and output options precede the `resume` subcommand. Documented `item.completed` agent messages produce progress; `turn.completed` events provide token usage. Command and MCP `item.started`/`item.completed` events expose bounded `codex_tool` progress with tool identity and phase, without arguments or tool results. Known unrelated MCP OAuth/configuration warnings are retained separately in bounded warnings; other provider failures keep their original classification. On failure, Harnest preserves observed downstream identity and cumulative usage without inventing a final result.

Before `codex exec`, the one-shot adapter performs a bounded, zero-inference native quota preflight through [`codex app-server` `account/rateLimits/read`](https://developers.openai.com/codex/app-server). Codex resolves its own native authentication; Harnest returns only the selected Codex bucket's usage percentage, derived headroom, window/reset values, source, and nullable `ordinaryUsageAllowed` flag. At 95% or more, or when that flag is false, it emits a bounded `codex_quota` warning before inference and records the same safe snapshot in `result.quota`. An absent permission flag remains null. An unavailable CLI, RPC error, malformed response, or deadline stays `status: "unknown"`; authentication and billing state are never substituted. The protocol does not prove that an account bucket applies to an explicit requested model or reserve, so the adapter preserves explicit provider/model pins and does not claim that the selected model is exhausted.

Cursor `cursor-agent --trust -p --output-format stream-json --stream-partial-output` is one-shot per invocation. The Cursor adapter must: map read-only policy to `--mode ask` and write policy to default agent mode with `--force` (always `--trust` to avoid prompts); pass an explicit `route.model` verbatim as `--model` and omit the flag otherwise; scope work with `--workspace request.cwd`; resume follow-ups with `--resume execution.sessionId`; fold stream-json deltas into `onProgress` as `cursor_delta` events and parse the terminal `type: result` envelope for `finalText`/`session_id`/`usage` (falling back to single-JSON then plain text); report `sessionId` (resumed or returned), a Harnest-owned `workflowRunId` (`cursor:<requestId>`), and bounded `eventSummary`; reject non-empty `tools` and non-null `maxCostUsd` with `kind: policy` rather than silently weakening them; never launch prompt text through a command shell (argv array only, including through the Windows PowerShell shim); and fail `control` closed as `unsupported-control`.

Claude `claude -p --output-format stream-json --verbose --permission-prompts none` is one-shot per invocation. The Claude adapter must: map read-only policy to `--permission-mode plan` and write policy to `acceptEdits`; map `policy.maxCostUsd` to `--max-budget-usd` and surface `total_cost_usd`/`num_turns` in `usage`; pass an explicit `route.model` verbatim as `--model` and omit the flag otherwise (the config chain is reliable); resume follow-ups with `--resume execution.sessionId`; fold assistant deltas into `onProgress` as `claude_delta` events and require the terminal `type: result` envelope (missing envelope and empty `result` are failures, guarding the known empty-result-with-tokens bug); classify `error_max_budget_usd` as `kind: budget` and other error subtypes as `downstream` with `permission_denials` preserved; report the envelope `session_id`, a Harnest-owned `workflowRunId` (`claude:<requestId>`), and bounded `eventSummary`; reject non-empty `tools` with `kind: policy`; never launch prompt text through a command shell; and fail `control` closed as `unsupported-control`.

Gemini is a prompt-only attached one-shot adapter. It requires exactly Gemini CLI v0.62.0 and must launch with temporary settings/admin policy that preserves native authentication while disabling inherited hooks, extensions and MCP servers. Preflight refuses any OS system-policy TOML because the adapter cannot override it. Read-only permits only the fixed safe read-tool allowlist and excludes shell and writes. Write policy adds the verified standard coding tools, including `run_shell_command` for build/test, `write_file`, and `replace`. Unknown tools, plan exit, MCP, extensions, and hooks remain denied. The cwd is the process directory, but inherited `includeDirectories` cannot be cleared; this policy is not a filesystem sandbox or read boundary. Plan mode alone is not an enforcement boundary. The adapter must stream structured events with persistence backpressure; require a native successful terminal result and nonempty bounded final text; preserve observed session/model/usage on failure; accept only supported explicit model pins; resume a later handoff through `execution.sessionId`; and reject unsupported policy, route, workflow, live-control, and `execution.transport: "session"` requests before inference. It must never use YOLO or approval-bypass behavior.

Amp is a prompt-only attached one-shot adapter; detached orbs are outside this contract. Native read-only is unsupported: workspace settings outrank custom settings and execute mode loads plugins with arbitrary local code, with no documented plugin-disable flag. The adapter therefore requires explicit `policy.write: true`, empty `policy.tools`, null `maxCostUsd`, and the write-approval marker before spawn. Generated restrictive settings reduce risk but are not a containment boundary. It accepts only `route.variant` values `low`, `medium`, `high`, or `ultra`; arbitrary model, provider and thinking fields fail before inference. Continuation retains the native thread mode, so a request combining `execution.sessionId` with `route.variant` must reject before preparation or spawn. An unobserved continuation mode remains unknown in the receipt. The adapter must stream structured events with persistence backpressure; require a native successful terminal result and nonempty bounded final text; preserve observed thread/usage on failure; continue a later handoff through `execution.sessionId`; and reject unsupported policy, workflow, live-control, and `execution.transport: "session"` requests before inference. Native Linux and macOS are supported. It must fail before spawn on native Windows unless the entire MCP server is running inside WSL.

While `run` is active, `control` accepts either a message (`steer` or `follow_up`) or a reroute for the next model request. It returns only after the downstream harness acknowledges the command. A send whose acknowledgement is lost must throw with `details.uncertain=true`; unsupported or rejected commands remain distinct. OpenCode (current) controls address the exact private-server session; legacy V1 1.18.18 controls fail closed because its active-session endpoint can deadlock the attached run. Pi controls reuse the active JSONL RPC process. Cursor, Claude, Codex, Gemini, Amp, and generic ACP runs have no interactive follow-up surface; their `control` must fail closed as `unsupported-control` without emulating unsafe mid-turn steering (follow up by resuming their sessions instead).

Policy `write` accepts legacy `readOnly`/`allowWrites` aliases when unambiguous; contradictory combinations with `policy.write` or between aliases are rejected rather than silently normalizing to read-only. OpenCode downstream failures containing `no such column: project_id` are surfaced with the original stderr/cause intact and a concise recovery hint: back up the database, update OpenCode, restart the server, and retry — never auto-delete, migrate, overwrite, or inspect the user's database.

Provider and model failures keep their evidence. When a harness reports an explicit provider error, all seven harness adapters classify authentication, billing, and region/opt-in rejections as `kind: "provider-auth"` and model-not-found/unavailable as `kind: "unavailable"`, carrying the provider label, the HTTP status when the payload carries one, and a bounded, credential-redacted provider reason; anything else stays `downstream` (or `transport`), and output with no classifiable evidence is never given an invented kind. An OpenCode V2 run against a private server (`route.serverUrl`) that fails without that evidence is reported as `unavailable` with a hint that the private server may lack the caller's provider authorization. A Pi credential failure names the provider and points at Pi's own auth store (`pi auth login --provider <provider>`). Spawned harnesses inherit the parent environment merged under adapter overrides so native authentication remains available under both read-only and write policies; no adapter reads, forwards, returns, or logs a provider credential value. Gemini receives a temporary settings location without copying credential material while retaining its native authentication home. Amp receives generated restrictive settings as risk reduction rather than containment. Both native clients continue to resolve authentication through supported mechanisms.

Codex `codex exec --json -o <last-message-file>` is one-shot per invocation. The Codex adapter must: map read-only policy to `--sandbox read-only` and write policy to `workspace-write` (never `danger-full-access` or `--dangerously-bypass-approvals`); pass an explicit `route.model` verbatim as `-m` and omit the flag otherwise; scope work with `-C request.cwd` (and spawn cwd); resume follow-ups with `exec resume <sessionId>`; treat the `-o` last-message file as authoritative `finalText` (empty file is a downstream failure) while folding `--json` deltas into `onProgress` as `codex_delta` events; report the scanned `sessionId` (or the resumed one), a Harnest-owned `workflowRunId` (`codex:<requestId>`), and bounded `eventSummary`; reject non-empty `tools` and non-null `maxCostUsd` with `kind: policy`; never launch prompt text through a command shell (argv array only, via the direct node entrypoint on Windows); and fail `control` closed as `unsupported-control`.
